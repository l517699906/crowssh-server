# 部署验证

部署命令返回零只代表该命令完成，不代表应用已经可用。按独立证据逐层验证。

1. 明确预期版本、服务名、端口和健康检查目标；缺少验收标准时先向用户确认，不自行发明成功条件。
2. 用 `statRemotePath` 或 `readRemoteText` 核对非敏感版本文件、部署清单或配置；需要比较候选与当前文件时用 `compareRemoteTexts`。
3. 调用 `inspectService` 验证进程和近期日志，调用 `inspectNetwork` 验证预期端口，必要时调用 `inspectSystem` 或 `inspectDisk` 排除宿主机资源阻塞。
4. 用 `executeCommand` 执行有限时、只读的本机健康检查或版本查询。记录 HTTP 状态、响应关键字段和真实退出码，不把单条成功日志当作健康证明。
5. 检查启动后是否持续稳定，关注重启次数、错误日志和依赖连接。若只能完成静态或本机验证，明确说明外部流量路径尚未验证。
6. 仅当版本、服务、端口、健康检查和错误日志均满足预期时报告部署成功。失败时给出阻塞证据和回滚条件；执行回滚或重启前重新取得确认。

验证过程保持只读。不得为了让检查通过而静默修改配置、关闭安全检查或删除失败证据。
