# 服务故障排查

先完成只读取证，再决定是否需要变更。

1. 明确服务名和用户看到的故障现象。调用 `inspectService` 获取 unit 属性、状态和有限行数的近期日志。
2. 若服务应监听端口，调用 `inspectNetwork` 验证实际监听状态；不要仅凭配置文件推断端口已生效。
3. 日志指向配置文件时，先用 `statRemotePath` 确认路径，再用 `readRemoteText` 分页读取必要片段。工具拒绝的敏感文件不得改用 `executeCommand` 强行读取。
4. 只有上述信息不足时，才用 `executeCommand` 运行服务自带的只读校验命令、版本查询或有限日志查询。
5. 按“直接证据、根因判断、候选修复、风险”输出。多个可能原因按证据强弱排序，不把相关性当作因果关系。
6. 启动、停止、重启、enable/disable、安装依赖或修改配置前先取得确认。变更后依次验证命令退出码、服务状态、监听端口和必要的健康检查。

同一失败命令不要无依据重复执行；被系统拦截的操作不得拆分或改写绕过。
